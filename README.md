# Stargazing — версія з окремою головною сторінкою та фотографіями

**Маршрути:** `/` — головна сторінка; `/products` — повний каталог із фільтрами, пошуком та сортуванням. Усі написи інтерфейсу українською, назва бренду — **Stargazing**.

**Фотографії:** використано реальні фотографії типів косметичних засобів, але самі 18 позицій каталогу та їхні ціни демонстраційні. Власники зображених торгових марок не пов'язані з цим навчальним проєктом. Авторство й посилання: `docs/PHOTO_SOURCES.md`.

## Оновлення вже запущеного сайту у WSL

1. Зупиніть Rails через `Ctrl+C` у терміналі, де він запущений.
2. Розпакуйте ZIP так, щоб було видно `Gemfile`, `app/`, `db/`, `config/`, і скопіюйте **вміст** нової папки в `~/Stargazing_Beauty_86` (не видаляйте власну базу даних!).
3. Із кореня проєкту виконайте:

```bash
cd ~/Stargazing_Beauty_86
ruby -v
ruby script/download_product_photos.rb  # рекомендовано для автономного показу фотографій
bin/rails db:seed                     # перейменує демонстраційні товари без втрати замовлень
bin/rails test
bin/rails server -b 0.0.0.0 -p 3001
```

Відкрийте `http://localhost:3001/` і `http://localhost:3001/products`.

**Важливо:** окремий `db:reset` не потрібний — він видалить локальні замовлення. Фотографії можна завантажити навіть після першого запуску. Якщо завантаження недоступне, браузер спробує показати їх напряму з Pexels за наявності інтернету.

# Stargazing Beauty & Wellness — курсова робота, тема №86

**Тема:** Розробка інтернет-магазину краси і здоров'я за допомогою Ruby on Rails.

Навчальний повноцінний Rails-проєкт із каталогом, пошуком, категоріями, реєстрацією, входом, кошиком, замовленнями, доставкою, демонстраційною оплатою, відгуками, формою зв'язку та адміністративною панеллю. Дані про товари вигадані та не є реальними торговими пропозиціями.

## Що нового у версії 3

- **Головна та каталог розділені**: `/` — презентація магазину з чотирма рекомендованими товарами, `/products` — повний каталог із пошуком і фільтрами.
- Видимі заголовки, написи, підказки й назви 18 демонстраційних товарів українською; оригінальна назва бренду **Stargazing** збережена.
- Замінено векторні ілюстрації товарів на реальні фотографії косметичних засобів із Pexels, із посиланнями на авторів і джерела у `docs/PHOTO_SOURCES.md`.
- Фото типів косметики ілюстративні: упаковка на світлині може не збігатися з вигаданою назвою товару.
- Додано команду локального завантаження фотографій для автономного показу на захисті.
- Повторне `bin/rails db:seed` перейменовує демонстраційні товари без скидання бази даних або історії замовлень.
- Збережено кошик, авторизацію, відгуки, доставку, навчальну оплату та адмінпанель.

**Для справжнього перегляду відкривайте сайт, запущений Rails**, за адресою `http://localhost:3001/`. У старому архіві був окремий статичний HTML-макет, але він більше не відповідає новій версії сайту, тому у цьому архіві його прибрано.

## Вимоги
- Ruby 3.2+
- Ruby on Rails 8.1.x (встановлюється через Bundler)
- SQLite3 dev-бібліотеки
- Інтернет тільки для першого встановлення gems, а також для вебшрифтів (без них є fallback)

## Запуск у WSL Ubuntu

```bash
sudo apt update
sudo apt install -y ruby-full ruby-dev build-essential libsqlite3-dev libyaml-dev libssl-dev zlib1g-dev git
ruby -v
# Має бути Ruby >= 3.2. Якщо apt встановив старішу версію, скористайтеся rbenv/ruby-build.
# Перейдіть у теку проєкту після розпакування:
cd ~/Stargazing_Beauty_86
# Якщо команда bundle недоступна:
gem install bundler --no-document
bundle install
bin/rails db:prepare
bin/rails db:seed
bin/rails server -b 0.0.0.0 -p 3001
```

Відкрийте **http://localhost:3001**. Якщо запускаєте з WSL на Windows, посилання доступне у звичайному браузері Windows.

> Не вводьте `rails new` усередині готової теки: це окремий готовий код застосунку, а не інструкція створення порожнього проєкту.

## Обліковий запис адміністратора

Адміністратор створюється **лише з локальних змінних середовища**. Приклад (встановіть власний пароль з 12+ символів):

```bash
export ADMIN_EMAIL='admin@local.test'
export ADMIN_PASSWORD='ЗАМІНІТЬ_НА_ВЛАСНИЙ_СКЛАДНИЙ_ПАРОЛЬ'
bin/rails db:seed
```

Після входу відкрити `/admin`. У production не використовуйте тестові адреси і не публікуйте секрети в GitHub.

## Перевірка

```bash
bin/rails test
bin/rails routes
bin/rails db:migrate:status
```

Окремо перевірте вручну: реєстрація → каталог → кошик → доставка/оплата → замовлення → відгук → звернення → адмінпанель. Перевіряйте також некоректну кількість, недостатні залишки й доступ без авторизації.

## Функції

- **Гість:** каталог із 18 товарами, пошук, фільтр за 6 категоріями, сортування, картка товару, обране, кошик, інформаційні сторінки, зворотний зв’язок.
- **Покупець:** усе вище, а також реєстрація, вхід, оформлення замовлення, історія та відгуки.
- **Адміністратор:** створення й редагування товарів, приховання товарів, перегляд замовлень і звернень, дозволені зміни статусів замовлень та повернення залишків при скасуванні.
- **Склад:** при замовленні останні залишки перевіряються в транзакції та блокуються через Active Record.

## Оплата і доставка — межі навчальної версії

Способи доставки (самовивіз, Нова пошта, Укрпошта) і тарифи **демонстраційні, без API перевізника**. Варіант `cod` означає вибір післяплати, а не проведену фінансову операцію. `demo_card` **не приймає даних картки й не списує коштів**; натискання кнопки лише змінює статус замовлення в тестовому оточенні. У production цей режим вимкнено. Для справжніх онлайн-платежів потрібна інтеграція сертифікованого платіжного провайдера, секретні ключі, webhook-підпис, idempotency та незалежне тестування.

## Структура

```text
app/controllers/    # HTTP-запити, авторизація й бізнес-сценарії
app/models/         # Active Record, валідації, транзакційне оформлення
app/views/          # шаблони ERB для сторінок
app/assets/         # CSS, фото товарів та допоміжні ілюстрації
config/routes.rb    # маршрути
config/database.yml # конфігурація SQLite
config/locales/     # українські переклади
db/migrate/         # схема бази даних
db/seeds.rb         # 6 категорій, 18 товарів
test/               # Minitest
docs/               # схема/макети й довідкові матеріали
```

## Розгортання

Цей пакет підготовлений насамперед для локальної демонстрації курсової. Для розміщення у відкритому інтернеті потрібні реальний сервер, домен, HTTPS, змінні `SECRET_KEY_BASE` та `APP_HOST`, постійне зберігання SQLite-файлу або перехід на PostgreSQL, резервні копії, моніторинг і додаткове security-тестування. **Фактичний деплой з цього пакета не виконано.** Застосунок не призначений для роботи з реальними картковими платежами без окремої інтеграції.
